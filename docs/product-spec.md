# Better 产品规格

## 1. 问题

用户并不缺待办事项，而是同时保留了太多方向，无法判断此刻最值得做什么。普通 Todo 会继续扩大积压，提醒工具只会更频繁地提醒一份没有优先级的清单。

Better 要解决的核心问题只有一个：在方向不清楚、又缺少现成客户和业务指标时，帮助用户选出今天唯一值得推进的行动，并在行动结束后留下可验证的证据。

## 2. 核心闭环

1. 最多保留三条“当前押注”，其余想法进入停车场。
2. 每条押注明确未来 7 天或 14 天希望改变的结果、证据门槛，以及当前最危险的假设。
3. 每天只能设一个焦点行动，并提前写下完成后会新增的证据。
4. 用一个有明确终点的专注计时段执行，而不是无限打磨。
5. 结束时记录实际证据、仍然未知的事情、现实变化和精力状态；没有证据也要如实记录。
6. 下一天的行动等这些信息回来后再决定，不预先写死整个周期。

## 3. 没有客户时如何衡量

产品不要求虚构收入或客户指标。证据按强度分为五级：

1. 问题证据：具体的人明确描述了问题和现有替代方案。
2. 尝试证据：真实的人愿意试用原型或让用户手工代办一次。
3. 返回证据：对方在没有催促的情况下再次使用或继续追问。
4. 承诺证据：对方愿意投入时间、数据、安装成本、介绍关系或其他稀缺资源。
5. 付费证据：对方愿意付费。

在取得第一位用户前，默认追踪“完成的访谈数、实际尝试人数、七天内主动返回人数、作出的承诺数”，不使用代码量、报告数、会话数和功能数作为价值指标。

工作任务或纯学习任务仍可使用“可交付产物”和“可复现理解”作为证据，但界面会明确提示它们弱于真实外部行为。

## 4. MVP 界面

- 主窗口：当前押注、今日唯一焦点、证据阶梯、停车场和最近记录。
- 菜单栏：显示当前焦点和剩余时间，可快速回到主窗口。
- 押注编辑：名称、7/14 天结果、周期证据门槛、危险假设；活跃押注硬上限为三条。
- 周期复盘：到达 7/14 天边界时汇总当期证据，保存结论，并选择继续、调整、完成或停放。
- 今日焦点：选择押注、填写一个可在当前专注段完成的行动、预期证据和证据类型。
- 专注计时：25、50 或 90 分钟；结束时发送本地通知。
- 收尾记录：实际证据、仍未知的问题、现实变化和精力状态；完成后清空今日焦点。
- Codex 滚动规划：按钮触发一次只读 `codex exec`，读取 Better 主动提供的有限摘要，只生成一个下一日建议；用户确认后才写入焦点。
- Better Coach：完成焦点后可进入连续对话；Better 保存专属 Codex 线程 ID 和最多 40 条本地可见消息，恢复失败时用结构化上下文重建线程。
- Git 上下文：用户逐个授权最多 8 个本地仓库；Coach 调用前读取本地分支、HEAD、工作区和最近提交快照。
- 提醒：每日开始提醒和每日收尾提醒，可关闭。

## 5. 决策规则

当用户不知道做什么时，应用根据候选行动回答五个问题并排序：

- 是否直接推进某条当前押注。
- 是否能在 48 小时内取得外部或可验证证据。
- 是否验证当前最危险的假设。
- 是否能在一个专注段内交付。
- 是否会新开项目或扩大长期维护面。

前四项加分，新开项目扣分。排序只作为解释透明的辅助，不替用户自动做决定。Codex 建议遵守同一规则，并必须解释它如何响应最近的实际情况。

## 6. 明确不做

- 不做通用 Todo、日历或项目管理系统。
- 不接入 GitHub、不自动发现本地仓库，也不扫描其他 Codex 会话和完整聊天档案；Coach 只接收用户明确授权的最小上下文。
- 不让 Codex 自动写数据、自动启动任务或批量生成一周任务表。
- 不自动生成无限任务，不设置连续打卡或游戏化积分。
- 不用通知制造焦虑；只提醒开始选择和结束复盘。
- 不以“完成了多少任务”作为成功指标。

## 7. 验收标准

- 第四条活跃押注无法创建，并给出明确错误。
- 同一时间只能存在一个今日焦点。
- 没有行动和预期证据时不能开始计时。
- 计时跨应用重启仍能按结束时间恢复。
- 焦点完成后形成证据记录并清空当前焦点。
- 本地数据可被正确保存、重新读取；损坏数据必须显示错误，不能静默覆盖。
- 核心约束和决策排序有自动化测试。
- Codex 运行在只读沙箱，结构化结果必须通过活跃押注、必填字段和时长校验，并经用户确认后才能采用。
- Coach 线程 ID、有限消息和待确认提案跨重启保持一致；线程恢复失败只能自动重建一次。
- 完成焦点后必须留下待复盘证据；成功完成一次 Coach 对话后清除待复盘标记。
- 周期复盘必须保存当期定义与证据统计；继续/调整开启新周期，完成/停放关闭当前周期。
- 周期复盘后旧 Coach 线程必须归档，下一次对话使用复盘结论建立新线程。
- Git 只执行本地只读命令；任何启用仓库刷新失败时必须阻止 Coach 调用，不能静默使用旧快照。

## 8. 原生体验改造

Better 应该在用户需要收拢注意力时随手可达，但不能替用户偷偷开始任务。

- 首次以 `Better.app` 启动时，默认注册为 macOS 登录项；用户可以在“提醒与启动”中关闭。
- 登录项注册失败或需要系统批准时，界面必须显示真实状态和处理入口，不能假装已经启用。
- 自动启动只打开应用和菜单栏入口，不自动创建焦点、不自动开始计时、不修改押注。
- 使用一枚正式的 macOS App Icon，并在侧边栏与菜单栏保持统一的“唯一焦点”品牌意象。
- 主界面通过稳定的深靛蓝、暖琥珀强调色、清晰卡片层级和更紧凑的信息密度建立辨识度，同时保持原生 SwiftUI 可访问性与深浅色模式适配。

### 涉及文件

- `Sources/LaunchAtLoginService.swift`：登录项状态、首次默认值、注册与取消注册。
- `Sources/BetterApp.swift`、`Sources/DashboardView.swift`、`Sources/TodayView.swift`、`Sources/ReminderSettingsView.swift`：启动接线与视觉层级。
- `Resources/Better.icns`、`Resources/Info.plist`、`scripts/build-app.sh`：应用图标打包。

### 新增验收标准

- `Better.app` 的 Bundle 包含并声明 `Better.icns`。
- 首次 App Bundle 启动会尝试注册登录项；用户关闭后，下次启动不会自行重新开启。
- 非 App Bundle 的开发启动明确显示登录项不可用，不崩溃也不谎报成功。
- 登录项设置不进入 `better.json`，不改变现有数据结构和当前焦点。

## 9. 图标实验室

图标不是一次性写死的品牌决定。Better 在侧边栏提供“图标实验室”，集中展示受控候选，让用户逐个比较并即时替换当前运行中的 Dock 与应用内图标。

- 选择写入 `UserDefaults`，不进入 `better.json`，不影响押注和焦点。
- 下次启动恢复上次选择。
- 原始方形候选在运行时统一放进带透明外角的 macOS squircle 安全框。
- 已经完成 squircle 设计的正式候选保持原始构图，不重复裁切。
- 资源缺失或损坏必须明确报错，不能显示错误图标后静默继续。
- Finder 中已签名 App Bundle 的静态图标继续使用 `Better.icns`；运行时选择不重写应用包。

“活星微光”候选保留 C1 的星星和左下生长意象，只增加克制的边缘微光与三颗稀疏亮点；不使用火焰、霓虹、轨道或小尺寸下会变成噪点的复杂特效。

其他角色不重复使用星光模板：北极星使用宽阔极光幕，引导星使用两层磁场涟漪，生长星使用低处晨雾呼吸。每组分别保留左、右构图，共形成六个独立效果候选。

## 10. Better Coach 连续闭环

Better Coach 是 Better 内部唯一的连续 Agent 角色，由本机已登录的 Codex CLI 提供。它拥有独立于开发会话和其他项目会话的专属线程。

- 新对话通过非临时 `codex exec --json` 建立，并保存 `thread.started.thread_id`。
- 后续对话通过 `codex exec resume <threadID>` 恢复。
- Better 的押注、证据、现实变化和已确认焦点始终是事实来源；线程 ID 只是延续自然语言上下文的句柄。
- 正常恢复只发送新增证据和当前状态；首次连接或故障重建发送最近 14 条证据、最多 12 条对话摘要和其他有限上下文。
- Coach 可以讨论和追问，但不能修改数据。结构化下一步先进入提案卡片，用户确认后才写入唯一焦点。
- Agent 只在用户发送、请求提案或未来明确授权的 Better 事件中运行，不持续扫描电脑或其他应用。

完整协议与验收标准见 [`better-coach-spec.md`](better-coach-spec.md)。

## 11. 周期复盘与线程轮换

押注不能因为到达日期而自动续期。用户必须回看当前周期内的证据，写下真实结论，然后选择继续、调整、完成或停放。

- 每次复盘保存押注定义快照、证据总数、外部证据数、最强证据类型和用户结论。
- 继续保持当前定义并从复盘日开启新周期。
- 调整允许重新定义结果、证据门槛、危险假设和 7/14 天长度。
- 完成或停放前必须结束该押注的当前焦点。
- 复盘会归档当前 Coach 线程 ID 和交接摘要，但保留有限本地消息。
- 下一次 Coach 对话创建新线程，并接收最近周期复盘。

完整状态转换见 [`cycle-review-spec.md`](cycle-review-spec.md)。

## 12. Git 上下文

Git 是用户明确授权的实现状态适配器，不是业务指标来源。

- 用户通过目录选择器逐个添加本地仓库，最多 8 个。
- Better 不扫描默认代码目录，不访问 GitHub，不执行 fetch、pull、push 或任何修改命令。
- 快照包括本地分支、HEAD、工作区状态、upstream ahead/behind 和最近 5 条提交。
- 打开 Git 页面、手动刷新以及每次 Coach 调用前会更新启用仓库。
- 任一启用仓库刷新失败会保存具体错误并取消本次 Coach 调用。
- 禁用仓库不刷新也不进入 Prompt；移除关注不会删除磁盘文件。
- Git activity 只能辅助理解实现进度，不能替代用户尝试、返回、承诺或付费证据。

完整安全边界与解析契约见 [`git-context-spec.md`](git-context-spec.md)。
