# Better 周期复盘与 Coach 轮换规格

## 1. 目标

把目前只有到期日期提示的 7/14 天押注，补成可追溯的周期闭环：查看当期证据、写下结论、决定继续/调整/完成/停放，并让 Better Coach 在新的事实边界上开始下一段对话。

本阶段同时补齐押注编辑，但不接入 Git、PR、日历或其他外部数据源。

## 2. 周期语义

- `createdAt` 保留押注首次创建时间。
- `cycleStartedAt` 表示当前周期开始时间；旧数据缺失时回退到 `createdAt`。
- `reviewDate` 从 `cycleStartedAt + horizonDays` 计算。
- 继续或调整押注会把 `cycleStartedAt` 重置为复盘时间。
- 完成或停放会关闭当前周期，不自动开启新周期。
- 重新激活已停放押注时，以重新激活时间开始新周期。

## 3. 周期复盘记录

每次复盘保存一条不可变 `BetCycleReview`，包含：

- 押注 ID 与标题快照。
- 周期开始、复盘时间和周期长度。
- 当期结果、证据门槛、最危险假设的快照。
- 当期证据总数、外部证据数和最强证据类型。
- 用户写下的真实结论。
- 决策：继续、调整、完成或停放。

历史记录不随押注后续编辑而改变。

## 4. 状态转换

### 4.1 继续

- 保持当前结果、证据门槛和危险假设。
- 保存复盘记录。
- 从复盘时间开启同长度的新周期。

### 4.2 调整

- 要求填写新的结果、证据门槛和危险假设，可切换 7/14 天。
- 保存旧周期快照后更新押注。
- 从复盘时间开启新周期。

### 4.3 完成

- 保存复盘记录并将状态改为 completed。
- 若该押注仍有当前焦点，明确拒绝关闭。

### 4.4 停放

- 保存复盘记录并将状态改为 parked。
- 若该押注仍有当前焦点，明确拒绝关闭。

## 5. Coach 线程轮换

完成任何一次周期复盘时：

- 如果存在当前 `threadID`，把线程 ID、归档时间、复盘原因、交接摘要和消息数量保存到最多 12 条的归档列表。
- 清空当前 `threadID`、线程时间、上下文指纹和待确认提案。
- 保留最多 40 条本地可见消息，作为界面连续性和下一线程的有限恢复上下文。
- 下一次发送消息或生成提案时，现有 Coach 服务会创建新线程，并发送完整上下文。
- 完整上下文新增最近 8 条周期复盘，确保新线程知道旧周期为什么结束以及策略如何变化。

线程归档只保存句柄和本地交接摘要，不复制 Codex rollout。

## 6. 押注编辑

- 活跃押注支持编辑名称、周期长度、周期结果、证据门槛和最危险假设。
- 编辑不会清空证据、重置周期或轮换 Coach 线程。
- 周期已经到期时仍可编辑文字字段，但不能借修改周期长度延后复盘；新周期长度只能在“调整”复盘中改变。
- 所有必填字段继续使用现有明确错误。

## 7. 界面

- 押注卡片显示“剩余 N 天”或“已到复盘日”。
- 到期押注提供醒目的“开始周期复盘”按钮；未到期也可从菜单提前复盘。
- 菜单新增“编辑押注”和“提前复盘”，不再直接从卡片标记完成。
- 复盘 Sheet 展示当期证据统计、结论输入和四种决策。
- 选择“调整”时展示新周期字段，默认填入当前内容。
- 押注页展示已停放、已完成和最近周期复盘。
- Coach 页面显示最近一次线程轮换状态。

## 8. 数据迁移

- 本阶段把 `BetterData.currentVersion` 升级为 3；后续 Git 上下文规格继续升级为 v4。
- v1/v2 缺少 `cycleReviews` 时解码为空数组。
- `Bet.cycleStartedAt` 与 `completedAt` 为可选字段，旧数据不需要自定义迁移。
- `CoachState.archivedThreads` 为可选数组，旧数据按空数组处理。
- 损坏 JSON 继续明确报错且不覆盖原文件。

## 9. 验收标准

- v1/v2 数据可读取为 v3，原押注、证据和 Coach 线程不丢失。
- 编辑押注不会改变 `cycleStartedAt`。
- 复盘统计只计算该押注当前周期内的证据。
- 继续/调整会重置周期开始时间；完成/停放会改变状态。
- 有当前焦点时不能完成或停放对应押注。
- 复盘后旧 Coach 线程进入归档，当前线程清空，本地消息保留。
- 新 Coach 完整上下文包含最近周期复盘。
- 核心检查、Debug/Release 构建和 App Bundle 打包通过。
